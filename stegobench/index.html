Project overview

One tool to compare image steganography fairly

Steganography hides a message inside an ordinary-looking image. Choosing a method is a trade-off: a message that survives JPEG compression is usually easier to detect. StegoBench measures that trade-off instead of guessing.

⚖

Fair comparison

Every method hides the same payload with the same error correction, so the scores are comparable.

⚡

Real-world attacks

JPEG, WebP, resizing, noise, blur, shifting, rotation and a social-media re-share chain.

◎

Detectors included

RS analysis, Weighted Stego and chi-square show how visible the hidden data is, with ROC curves.

∑

Numbers you can trust

Run a whole folder of images: mean ± standard deviation and significance tests, not one lucky result.

🔒

Private by design

Images and secrets never leave your device. The secret is encrypted with a passphrase before hiding.

⟲

Reproducible

Reports include browser, image hashes and settings, and export to CSV, JSON or PDF.

How it works

From a secret to a ranked leaderboard in five steps

  1. 1

    Choose cover & secret

    Pick one image or a whole folder. Type a message or choose a file, then set a passphrase.

  2. 2

    Protect the payload

    The secret is encrypted (AES-256-GCM), wrapped with a length and checksum, and protected with Reed-Solomon error correction.

  3. 3

    Hide it

    Each selected method embeds the bits: LSB variants, DCT, spread spectrum, DWT or content-adaptive S-UNIWARD.

  4. 4

    Attack and extract

    The stego image is attacked, then the message is extracted again with the same key and compared with the original.

  5. 5

    Score & rank

    Robustness, invisibility, detectability and capacity are combined into a ranking you can reweight for your goal.

Attack steps

What happens inside one attack test

For every method and every attack, StegoBench repeats the same six steps and records how much of the message survived.

  1. 1
    Take the stego image

    The image that already contains the hidden bits (lossless PNG, or saved as JPEG QF 90 if you chose the JPEG carrier).

  2. 2
    Apply the attack

    For example a real browser JPEG re-encode at quality 75, a 50% resize, Gaussian noise, or a 3-pixel shift.

  3. 3
    Extract with the same key

    The method reads the bits back from the attacked image. It never sees the original cover (blind extraction).

  4. 4
    Correct errors

    Reed-Solomon decoding repairs flipped bytes when ECC is on, for every method equally.

  5. 5
    Compare with the original

    Recovery is chance-adjusted: a 50% bit match counts as 0%, a perfect match as 100%. A ✓ means the whole message came back.

  6. 6
    Add to the scores

    All attacks average into the robustness score and fill one row of the heat-map.

Methods

Eight ways to hide data, from simple to state of the art

Sequential LSBSpatial

Replaces the lowest bit of the first pixels. Huge capacity, no robustness.

Random LSBSpatial

Same, at key-chosen random positions.

LSB Matching ±1Spatial

Adds or subtracts 1 instead of overwriting, which defeats the classic chi-square test.

S-UNIWARD + STCAdaptive

Puts changes in textured areas using wavelet costs and syndrome-trellis codes.

DCT (Koch-Zhao)Transform

Encodes one bit per 8×8 block in the order of two DCT coefficients.

DCT + VoteHybrid

Repeats each bit in several blocks and decodes by majority vote.

Spread SpectrumTransform

A faint key-based noise pattern, found again by correlation.

DWT-QIM (Haar)Transform

Quantises wavelet coefficients with a secret dither.
